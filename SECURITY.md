# CHLOM Security Policy

**Phase 3 edition — effective 2026-08-26**

CHLOM handles governance, rights, evidence, integration, certification, and machine-readable institutional records. Security reports must preserve the public/private boundary and avoid exposing sensitive operational material in public issues or pull requests.

## Report privately

Send sensitive reports to **contact@crownthrive.com** with `CHLOM SECURITY` in the subject.

Do not publicly post secret values, private personal/customer data, restricted evidence, private contracts, protected evaluation material, private economic logic, exploit-enabling instructions, or other restricted CrownThrive information.

## Include

Provide the affected repository path/component/version, observed behavior, impact, reproducibility conditions, evidence sufficient to investigate without unnecessary private data, and any known containment or rollback information.

## Scope distinctions

A security report must distinguish among repository/source risk, deployed-runtime risk, provider/integration risk, evidence-integrity risk, rights/authorization risk, and projection/documentation risk. A public page inconsistency is not automatically a runtime vulnerability; a provider capability is not automatically CrownThrive write authority.

## Coordinated handling

CrownThrive may validate, classify, contain, patch, rotate/revoke affected access where authorized, preserve evidence, test rollback/recovery, update certification state, and issue a public-safe advisory when appropriate.

No report or patch automatically grants the reporter access, compensation, ownership, certification, license rights, or permission to test systems beyond authority separately granted.

## Phase 3 fail-closed rule

If a security finding materially undermines an operation-level certification, affected authority should fail closed or be placed on hold until the governing evidence supports restoration. Historical evidence remains preserved; current state is corrected prospectively through CrownThrive OS and CHLOM records.

## Supported policy lineage

Current Phase 3 records are the active policy line. Historical architecture and prior certification generations remain available for audit/history but do not supersede current security controls.
