# Phase 2.5 — Convergent Spine Alignment

**Baseline:** 2026-08-17  
**Purpose:** reconcile Phase 2 CHLOM governance recovery with the current CrownThrive Holdings business-plan asset model before Phase 3 implementation.

## Why Phase 2.5 exists

CrownThrive is actively building. Older records, recovered help-center material, current production properties, new portfolio concepts, and the proposed holding-company structure must coexist without losing lineage or allowing stale descriptions to become accidental truth.

Phase 2.5 therefore treats the ecosystem as a governed, fluid portfolio. Identity persists; status changes. Legacy descriptions remain recoverable; canonical descriptions may supersede them. A product, domain, script, or platform card is not considered commercially live merely because it exists in a registry.

## Combined merge strategy

This branch was created **from the Phase 2 head commit** (`7c2a03bf089ffd4a402e271e2ed2312dd7bf2fef`). Therefore a pull request from `phase-2.5/convergent-spine` directly to `main` contains **Phase 2 plus Phase 2.5**. The user does not need to merge Phase 2 first.

Once this combined PR is validated, the earlier Phase 2-only PR should be treated as superseded to prevent duplicate/conflicting merge paths.

## Proposed institutional layering

1. **CrownThrive Holdings** — proposed portfolio stewardship, capital allocation, governance, long-term ownership and succession layer. Final legal/tax/intercompany design requires counsel.
2. **CrownThrive, LLC** — operating company and hybrid incubator. Runs shared infrastructure, customer delivery, memberships, services, support, partnerships and portfolio execution.
3. **CHLOM / IP structure** — rights, provenance, permissions, licenses, entitlements, splits, evidence, audit and remedies. Its final legal/entity position remains to be determined.
4. **CII / ThriveFund** — impact and reinvestment governance. Do not imply nonprofit status unless formally established.
5. **Media / physical SPVs** — case-by-case risk-separated entities when material liability, real estate, capital expenditure, franchise exposure or outside investment warrants separation.

## Shared operating spine

Every active corridor should progressively consume the same shared services:

- CrownThrive ID — identity, SSO, roles, consent and permissions.
- CrownThrive IO / MCP — API gateway, tool routing, integrations, metering and agent connectivity.
- CHLOM — rights, licensing, provenance, eligibility, splits, expiration, audit and remedies.
- OpsOasis + Collab Portal — execution, projects, approvals, signatures and controlled collaboration.
- CrownThrive Support + CrownInsights — help center, knowledge, SOPs, onboarding, tickets, AI triage and customer success.
- CrownLytics + CrownPulse + ThrivePush — measurement, normalized events, intelligence, signals and permissioned communication.
- CrownRewards + Partnero — retention, incentives, referrals, affiliates, ambassadors and progression.

## Portfolio control rules

- Each public brand must own a clear customer problem and canonical promise.
- Each active asset needs an accountable owner, canonical domain, customer, revenue model, support path, lifecycle status, rights record and analytics events.
- Status is mutable; stable asset IDs and lineage are persistent.
- New concepts enter as incubate/reserve/build before being promoted to live.
- Existing history, URLs, content and user records are preserved unless deletion is legally required or explicitly approved.
- Third-party SaaS may not hold the sole copy of institutional knowledge, roadmaps, rights records or critical customer data.
- CHLOM should govern material IP, permissions, licensing and auditable routing, but public repositories must not contain restricted source material or secrets.

## Phase 3 gate

Phase 3 can begin after the combined Phase 2 + 2.5 branch is merged and becomes the canonical base. Phase 3 should implement the operating services against these registries rather than hard-coding assumptions into isolated platforms.
